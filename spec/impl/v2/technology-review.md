# V2 Technology Decision Review

This is a descriptive review of prior choices, not a v2 dependency lock or permission to execute the old stack. Versions below are historical pins from the v1 records, not claims about the latest or safest available release. No package was installed, built or tested for this review. Existing exact-scope selections remain historical facts. The concrete v2 profile selects SQLite, Git checkpoints, Codex app-server over local stdio and the minimal security posture. Exact dependency versions/features still need qualification; selection is not capacity or production-readiness evidence.

## Recommended Shape

Use a small Rust application with one local SQLite controller, Git source checkpoints, a private application interface and Duvet Cap. Use Codex for extended agent work and a bounded native request path for simpler definitions. Use ordinary host access with optional SSH forwarding; remove the initial content-encryption system, its C2 profile and all key/secret-service dependencies. No separate immutable-byte service, sandbox platform, programmable policy engine or backup stack is an initial prerequisite.

This changes what the implementation owns. It does not replace authentication with caller assertions, remove transaction recovery, make all dependencies simulation-tested, or prove the full scale target.

## Complete Historical Inventory Coverage

The source inventory contains 19 consumption-boundary rows, 71 Cargo-consumer rows, 65 pinned dependency identities, eight active Wasmi entries and thirteen metadata-only Wasmi entries: 176 data rows across16 sections. These are overlapping roles and projections, not176 independent product choices. The accompanying validation receipt enumerates every row and its review disposition.

The 71 Cargo consumers are historical implementation sites, not a prescribed v2 crate graph. Keep required task, authority, event, deadline, result and recovery behavior; consolidate actual shared mechanisms. Drop content-key/envelope paths; defer elaborate workspace lineage, programmable deciders and custom model-loop internals. Re-evaluate every site's dependency closure from the new source instead of copying old manifests.

All65 dependency entries remain recorded once in [the v1 inventory](../v1/technology-inventory.md#pinned-rust-dependency-identities). The review disposition is to derive only the selected v2 target/build/test closure, with direct roles T04/T06/T08/T14/T24/T25 supplying its purpose. Optional platform entries, duplicate RNG or syntax-tree versions, macro generators and target-only WASI records are not automatically built or newly approved. The eight Wasmi entries and all thirteen metadata-only entries share the deferred T22/T23 disposition. The specific wasmi_ir build.rs and fourteen helpers remain a historical narrow generator selection.

Prior83-package native,162-package transport,28-identity crypto,73-package C2,128/131 development and other combined counts describe different source/feature projections. They cannot be added or treated as one production lock. Many underlying linked inventories were intentionally deleted with the implementation. This review can verify the surviving choices, versions and scope, but cannot claim a new archive, security or compiled-transitive-dependency audit of missing payloads.

Sections covering build bundles, historical out-of-scope use, adapter parity and evidence inputs have been included. The old45-ELF inventory is evidence about an old run, not a requirement to recreate45 binaries. Proposal banners are historical where later decision records supersede them.

## Review Method And Sources

The local basis is the full [v1 technology inventory](../v1/technology-inventory.md), [v1 decisions](../v1/decisions.md), technology proposal families under [v1 proposals](../v1/proposals/), the [engine/codec comparison](../v1/proposals/implementation-draft/engine-codec-qualification.md), and the retained [retrospective](../../../../borg-runtime/docs/retrospective/retrospective.json). Original external URLs in those records remain research sources; this pass is not a fresh security/version audit of every product.

Current Codex integration guidance was checked during this discussion: [app-server](https://learn.chatgpt.com/docs/app-server), [non-interactive execution](https://learn.chatgpt.com/docs/non-interactive-mode), and [harness integration choices](https://developers.openai.com/blog/codex-as-a-platform). The [Agent Substrate assessment](../../../../borg-runtime/docs/retrospective/agent-substrate-research.json) records the inspected release and concrete storage/authorization limitations. Neither source is a production qualification result.

The profile choices are settled as recorded in the decision record. Remaining preparation is exact dependency/client version and feature pinning, worker process/account layout, resource limits and qualification. Local credential configuration is not a new key-service choice. This avoids optimizing a large dependency inventory for components v2 no longer needs. SSH forwarding behavior is documented by the [OpenSSH manual](https://man.openbsd.org/ssh).

The SQLite selection follows its [application-server guidance](https://www.sqlite.org/whentouse.html); [WAL constraints and corrected builds](https://www.sqlite.org/wal.html) remain qualification inputs. No workload or durability result is inferred from selecting the engine.

The [exact proposed dependency profile](dependency-profile.md) is the current follow-through on this family review. It distinguishes selected technology families from proposed releases/features, states the SQLite source/client pairing and updated JSON validation profile, and keeps missing transitive resolution/build evidence explicit.

The [worker-wide resource selection](decisions.md#worker-wide-resource-group-selected) uses the Linux kernel's cgroup v2 facility through ordinary host startup configuration. No new runtime library, service manager, resource-management service or package acquisition follows from this selection. Exact host controls and limits still need qualification; filesystem quota technology remains separate and unselected.
