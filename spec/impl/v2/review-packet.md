# V2 Build Packet

The specification and four component work packages are prepared for review. The accepted product scope is concrete: trusted one-tenant workers, local SQLite controller, Codex coding tasks plus bounded native tasks, Git checkpoints, a browser collaboration UI and behavior-based validation. Every workspace can build. The permission engine, encryption/key services, strong sandboxing, backup/HA and the recorded broader facilities are outside the initial profile.

## First Usable Result

Create a task in the browser; run the real supplied executor in a checkout; edit, build and test source; publish an exact Git checkpoint; commit the accepted result; show its code and validation links; restart the controller and display the same durable task/result. A successful executor exit with failed acceptance checks is not success. A lost acknowledgment, disconnected worker or unavailable conversation history is not silently treated as completed work.

The first controller-worker smoke test can run before the UI completes. The user-facing journey requires the browser. Native execution, delegation and full-scale qualification do not block either first coding integration; they join the same application afterward.

## Four Complete Batches And One Integrator

| Owner | Whole delivery | Real completion |
|---|---|---|
| Controller | SQLite records/transitions, API, assignment, bounded oldest-eligible scheduling, concurrent sessions sharing agent memory, one current execution per session, restart/recovery | Actual database/consumer tests; no uncompiled state-machine handoff. |
| Coding worker | Codex stdio, process ownership/cleanup, checkout/build/test, Git checkpoint and outcome reconciliation | Real executor and repository, then the real controller join. |
| Native executor | Bounded provider requests, output schemas, deadlines/budgets and child-task integration | Controlled and actual provider evidence distinguished; joined durable results and delegation. |
| Browser collaboration | Task list/details, submit/assign, status/progress/output, dependencies, cancel/retry and code/results | Actual browser/controller/worker journey, including failed/uncertain operations and restart. |
| Integrator | One package/lock, shared protocol, entry points and integrated tests | Keeps the real journey runnable and integrates completed commits promptly. |

The [execution plan](execution-plan.md#parallel-delivery-batches) contains the full work orders, exclusive source/test boundaries, useful first handoffs and acceptance IDs. Each owner implements, builds, tests and fixes its batch. There is no routine peer-message requirement or separate author/reviewer/runner chain for every small change. Shared interface changes go through the single integrator. Owners share exact pushed WIP commits, never another worker's mutable checkout.

There are five capabilities, six capability dependencies, twelve milestones and eight delivery views. The browser completion now explicitly depends on the real coding journey; that one added dependency closes the actual UI acceptance without delaying independent browser source work. The later ten-host milestone is not a first-release prerequisite.

## Current Agent And Session Correction

The stable template/definition identity is the durable agent identity. Sessions instantiate that agent and share its explicit memory; task and attempt identities remain distinct. Concurrent sessions are permitted while each session retains its own fenced execution and pinned definition revision. The selected development transition resets controller task/session/memory data and worker execution state after verified shutdown, retaining repositories, source commits, credentials and separate evidence. The clean successor is wire6/schema10/worker8; prototype backward compatibility is not required. This source record does not claim the reset or successor rollout has occurred.
