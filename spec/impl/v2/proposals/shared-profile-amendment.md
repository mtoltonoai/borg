## Selected Initial Boundary

The first release is a trusted one-tenant task system with one local controller, native and supplied executors, durable task/attempt/history/memory and accepted results, explicit Git source checkpoints and a browser collaboration interface. Every coding workspace can build/test. Host/SSH, repository and provider access controls remain; a fine-grained application permission engine is deferred. Protected exact-revision merge checks and designated human final rollout remain.

The reviewed reductions explicitly set aside content encryption and key/secret services, hostile-workload containment, per-call assertions/credential brokers, generic decision-hook execution, full native inner-harness state, backup/disaster recovery, automatic controller failover and automatic complete-workspace snapshots. Additional selected deferrals are general pubsub/webhooks/recurring user timers, keyed-session/partition machinery, complete transcript/tail/upload facilities, per-inner-reply charter auditing, automatic experiments/learning/observation pipelines and advanced collaboration housekeeping/ingestion/person-notification/recovery workflows.

Task notifications, worker command wakes, execution deadlines, accepted outputs, explicit agent memory, definition/source provenance and measured usage remain. Scheduling is oldest eligible within bounded executor capacity; one agent identity has one active execution, while many agents can share a template. Definitions are immutable direct revisions; stored task schema changes have explicit migration dispositions. The binding rules record these replacements without pretending the old full-session contracts are satisfied.

## Retained Original Details

The retained group includes applicable specification/change-process discipline, implementation identity/source/evidence attribution, actual authentication, one-tenant bootstrap/no-registration, protected checker behavior and relevant evidence-record property/subject/result/scope/reproduction details. These remain exact original references, not duplicated new v2 prose or blanket implementation credit. Source-specific conditions and optional behavior remain visible in the binding source.

In particular, SSH authentication is not a signed-assertion implementation; bounded task output is not a provider-neutral complete transcript; a Git checkpoint is not a task-database backup or complete filesystem snapshot; task generations are not distributed partition leases; and browser refresh is not the original tokenized viewer/topic-tail protocol.

## Compatibility Disposition

The proposed task API declares its own wire revision and does not masquerade as the old signed-assertion, stored-form, event-envelope or full-session endpoints. Existing consumers remain at their old targets. No existing data is silently reinterpreted. A non-additive change for an actually deployed consumer still requires an explicit version and migration path; deleting the private prototype did not prove no other deployments exist.

The old native report, source snapshot, rule receipts and planning results remain historical. Current binding and generated-output hashes identify this proposal. Shared conformance and execution readiness are not inferred from complete accounting or from the normative presentation of intended v2 requirements.

Integrated semantic review narrows the old zero-loss-drain claim to committed task state and acknowledged source checkpoints. Generic wait/resolver clauses now either refer precisely to the two v2 task relations or are explicit replacements; they do not reactivate document/question/review resolution, old blocked-state restoration or complete drain semantics.
