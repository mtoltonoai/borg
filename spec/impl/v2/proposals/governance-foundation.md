# Focused Governance Acceptance

This is the finite acceptance matrix for the four approved additions. It describes required implementation, not executed tests or a new shared outcome. Existing host access and protected-release approval remain unchanged. Use ordinary targets and the existing controller/worker/native/browser test machinery; no parallel store, generic policy engine, new reviewer service or per-case runner is required.

| Family | Existing producer reused | Missing real acceptance | Primary allocation |
|---|---|---|---|
| Completion | Controller acceptance, explicit waits, native/Codex safe inputs and exact input ACK | Both completion/input race orders; required work vs optional question; bounded concrete reason; actual consumed input; consecutive bound/exhaustion; evaluator failure; independent-event reset; restart and stale-owner refusal; original deadline/budget/unknown effect preserved | V2_STORE STOP_ADMISSION plus INTEGRATED_WORKER, NATIVE_INTEGRATION and COLLAB_JOIN CONSUMERS |
| Configuration | Closed twelve-field update, three CAS comparisons, immutable revisions, effective validation and original receipt | Exact classification-rule binding, before/after under one defaults revision, unspecified and unknown-field comparison, no self/ancestor governance weakening, trusted configured class, rollback/replay and exact comparison audit; no policy field or accepted-task hot reload | V2_STORE CONFIGURATION_APPLY |
| Decision rules | Existing canonical operations, durable audit/event owner, deterministic validators | Exact rule/subject/provenance/outcome record; transactional enforcing event; no duplicate decision on lost ACK; real shadow counterfactual even after refusal, no effects/delay; failed/stale/wrong-version promotion refusal and valid evidence-bound promotion; immutable safety still enforced | V2_STORE DECISION_RULES |
| Independent control | Trusted host invocation, original stop command and worker closure/recovery | Broken ordinary evaluator cannot block authorized stop/pause; caller-supplied provenance denied; hold survives config/restart; exact override prior/replacement/expiry audit; crash around expiry, normal explicit supersession, closed admission on unknown expiry; no implicit resume or protected bypass | V2_STORE EMERGENCY_CONTROLS plus RECOVERY CANCEL and PRODUCT |

Each positive result uses the actual producer and consumer named by its gate. Prospective fixture counts, source annotations, native planning coverage, process exit alone and a model's own report do not establish acceptance. Preserve failed runs and distinguish component qualification from both actual executor joins. Decision evidence carries no credentials or unbounded rejected content. Current implementation has none of the new gates qualified by this proposal.

Root composition preserves all earlier exact requirement identities, merges the concurrent charter patch by clause/section rather than overwriting whole files, updates implementation-review provenance and the native source selection after composition, and runs the existing normal/strict extractor/planner route. Full shared gate selection, shared files and the real runtime lock remain untouched.
