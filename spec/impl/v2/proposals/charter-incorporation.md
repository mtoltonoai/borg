## Immutable Inputs And Live Adoption

The initial charter source belongs to the accepted definition. Existing complete immutable definition or document-version identities are reused when they resolve all authoritative source; rendering or compaction is not source authority. Exact clause references retain file, stable section and exact sentence within that revision. Existing access rules apply, and a logical source filename does not grant filesystem or network access.

A live charter update is a separate narrow canonical operation and pending/effective session binding. Native adoption retains its next-model-turn behavior. A supplied-executor update without a qualified public boundary remains pending or unsupported; it does not cause a restart, duplicate send or fabricated adoption. It preserves original operation identity and compares the current binding before accepting an immutable successor. It does not mutate accepted TaskInput, selected inference, tools, budget, limits or prior replies. The existing twelve-field limit update remains limit-only and future-only. Selecting a new agent head is not evidence that a running session adopted it.

A native model request uses an acknowledged effective binding selected at the actual next-turn boundary. A change arriving during a tool call waits until its result is committed. Recovery checks the pending binding on load, retains historical effective bindings and resolves uncertain original operations without resending model or tool effects. An idle session is not woken merely to adopt the change.

The original incorporation identified native update delivery and debounced compaction as implementation work. Their selected acceptance remains unchanged: the configuration change triggers them independently of citation audit findings, and actual selected executor/provider behavior needs its durable completion association. Scheduling a flag or appending text alone does not demonstrate it; existing native qualification remains bound to its actual source and results.

## Reply Records And Passive Audit

Each native reply and supplied outer-turn final result needs a durable original occurrence association, its effective or delivered authoritative revision, original declared clause references and structural check outcome. The supplied final-output surface requests genuine declarations; hidden internal replies are outside this explicit exception. A host source binding never substitutes for a model declaration. Missing or malformed metadata remains identifiable as missing or malformed; host bookkeeping does not fill in governing clauses or turn absence into a valid empty declaration. A reply cited by a task result/history/audit view retains this association. A lookup receipt never substitutes for the original reply or update receipt.

Checking compares revision/file/section/exact sentence with retained authoritative source. It records invalid or mismatched references with their reply. It does not prove the behavior complied, and does not itself produce corrective prompts, retry, reset, blocking, compaction, a model judge or new authority. Independent output validation and durable operation ordering still apply. A storage failure is reconciled through existing recovery rather than disguising an unknown request as an empty successful reply.
